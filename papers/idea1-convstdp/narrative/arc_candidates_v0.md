## 弧 A：方法论优先 ——「双轨协议解耦 encoder 与读出」

**一句话卖点**：第一个把 VPR 用 SNN 的"特征质量"与"读出适配"解耦测量的工作——借此严格定位无 BP 卷积可塑性的真实贡献发生在哪一层。

**故事线**：VPR-SNN 的端到端 Recall 混杂了 encoder 与 spike-forcing 读出两个因素，既往工作无法分辨增益来源；我们用双轨协议（轨A 经读出层 / 轨B 绕开读出层做特征检索）把它拆开，并以此为工具检验一个具体问题：无 BP 的竞争性 Hebbian 卷积前端能否学到空间结构。

**依赖哪些实验结果成立**：
- 必需：双轨全套数据（B0–B5 × 3 seeds）——轨A/轨B 出现**有信息量的差异**（至少某个变体两轨表现不一致，否则协议本身没展示出价值）；
- 必需：Gate 1（轨B B2 > B1）；
- 不需要 Gate 2：轨A 不增益时，"失配定位"本身就是发现（退路内置，见 PLAN §6）。

**最大审稿攻击点**："这只是消融换了个名字。"——若双轨数字同涨同跌、差异平淡，协议就退化成普通消融表，方法论贡献瞬间蒸发。
**一句话回应预案**：双轨的价值恰恰在于它预注册了"失配"这一可证伪结果；任一方向的差异（含失配）都产生单轨消融给不出的结论，且轨B 协议可复用于任何 VPR 编码器。

**机制锚点**：双轨 = 轨A `run_inference` vs 轨B `eval_retrieval.py`（PLAN S1.4）；"无 BP"= 局部 winner 相关更新 vs LoCS-Net 端到端反传。

## 弧 B：空位/机制发现优先 ——「无 BP 可塑性涌现出类 Gabor 结构」

**一句话卖点**：第一条无 BP、单步的 VPR 卷积前端——竞争性 Hebbian 可塑性自发涌现出 oriented edge / 中心-外周结构，且（若 Gate 1.5 通过）达到或超越手工 Gabor 滤波器组。

**故事线**：conv-STDP 在物体识别里能学到类 Gabor 结构（Kheradpisheh 系），但依赖多步时延编码；我们证明单步幅度域规则在 VPR 任务上同样涌现该结构——把"可解释的涌现特征"带进 VPR，并且整个训练没有一个梯度。

**依赖哪些实验结果成立**：
- 必需：Gate 1（轨B B2 > B1）；
- 必需：Figure 2 核形态证据（Gabor 拟合 R² 分布显著高于随机初始化，方向选择性分布、DC/AC 比下降——PLAN S3.1/S2.3 验收断言）；
- 强依赖：Gate 1.5（B2 ≥ B5）——若 B5 反超，弧 B 降级为"零设计成本追平手工设计"，卖点明显减弱；
- 理想情况还要 Gate 2（轨A 增益），否则只是"前端现象学"论文。

**最大审稿攻击点**：核可视化的 cherry-picking 质疑——"你挑了最好看的几个核"。
**一句话回应预案**：全部 C 个核的拟合优度以分布形式报告（中位数 + IQR + 统计检验），附图展示完整核网格而非精选子集；随机初始化同图并列。
**次生攻击点**："涌现 Gabor 在 2018 年就不是新闻了"——回应：新颖性不在 Gabor 本身，而在**单步无 BP 规则 + VPR 任务 + 与读出层的适配分析**三者的组合。

**机制锚点**：核形态 = `conv_layer.w.weight` 可视化与 Gabor 拟合（PLAN S3.1）；单步幅度域 vs Kheradpisheh 多步时延编码。

## 弧 C：效率/系统优先 ——「以 ~1/T 开销获得多步 conv-SNN 的空间结构」

**一句话卖点**：VPR 的 SNN 可以既有空间结构、又保持极速训练——单步幅度域规则以约 1/T 的训练开销达到多步 conv-SNN 方法的可比检索质量。

**故事线**：多步 SNN（SpikingJelly 系 conv-STDP、LoCS-Net 的 LIF 转换路线）的空间结构是用 T 步仿真和/或 BP 买来的；SNN-Places 等工作的训练复杂度已被审稿人批评过（用户陈述，细节待核实）。我们把空间归纳偏置的成本打回单步量级。

**依赖哪些实验结果成立**：
- 必需：Table 4 效率数据（训练墙钟、FLOPs、内存，B0/B2/B4 三列 + SpikingJelly 参照行）；
- 必需：轨B 上 B2 与多步参照的差距足够小（"可比"需要数字支撑）；
- 对 Gate 1/2 要求中等，但**若 B2 性能明显低于多步参照，"省开销"会被读成"省性能"**，弧线崩塌。

**最大审稿攻击点**：效率对比的公平性——"你的快是因为实现简单/任务小/硬件不对等"。
**一句话回应预案**：效率主张只做**结构化对比**（单步 vs T 步的渐近开销比、FLOPs 解析式），不声称实现级跑赢；所有数字同硬件同数据通路采集。

**机制锚点**：单步规则 vs 多步 trace（PLAN S3.5 参照行）；conv 单样本更新量 = N_win×k² vs 全连接 tile [in,out]（PLAN ADR-3 内存对比）。

## 我的倾向与理由

**推荐：弧 A 为主叙事脊柱，弧 B 的 Figure 2 作第二幕证据，弧 C 降级为支撑段落（Table 4）。**

理由：
1. **稳健性**：弧 A 是唯一在 Gate 2 失败时故事仍完整的弧——以目前零数据的状态，脊柱必须选活路最多的；
2. **纪律兼容**：弧 A 的每条措辞都能指到代码级机制差异（双轨脚本、layer_dict、conv2d_weight），不含依赖运气的修辞；弧 B 的"涌现"措辞在核图出来之前全部是空头支票；
3. **可升级性**：若 Gate 1/1.5/2 全过，弧 A 的骨架可以原地升级为"方法论 + 机制发现"双卖点（弧 B 证据插入第二幕），不需要推翻重写；反过来从弧 B 降级到弧 A 则要重写 intro；
4. 弧 C 的效率论据无论选哪条弧都会出现在 Table 4——它作为段落比作为脊柱更诚实（我们的前端相对 B0 是**增加**开销的，效率只对多步方法成立）。
