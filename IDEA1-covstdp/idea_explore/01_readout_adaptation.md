# 方向 1：读出适配（Readout Adaptation）——把 8.3pt 差距变成贡献

> 2026-09-13｜来源：PLAN §5b 归档改造 I3（读出探针表）的升级版
> 核心资产：B5 3300 地 轨B P@100%R=0.802 > LoCS-Net 78.6%，但系统级轨A 0.719 < 0.786。
> 轨B−轨A = 8.3pt 已被双轨协议精确定位到 **spike-forcing 读出层**——这是全文最大的可转化资产。

## 0. 预注册故事线（写死再跑）

- **主张**：VPRTempo 的 spike-forcing 读出层是规模下的信息瓶颈；特征质量已超 BP 方案，差距可定位、可量化、可无 BP 修复。
- **判据（提前承诺）**：
  - 诊断成立：探针表显示存在某个读出变体在 3300 地轨A R@1 显著高于 spike-forcing（≥ +3pt，单 seed 迭代档即可），证明"丢分是读出的属性，不是特征的属性"；
  - 修复成功：无 BP 修复方案在 3300 地轨A R@1 ≥ B5 基线 +3pt 且 500 地不降；
  - 故事成立（stretch）：系统级轨A P@100%R 对 LoCS-Net 差距收窄 ≥50%（0.719 → ≥0.753；追平 0.786 为上限目标）。
- **失败出口**：若所有探针 ≈ spike-forcing（差距真在特征→output 的信息论压缩上），转为"机制解剖"分析型小节（各探针的差值分解本身就是可写的发现），零损失。

## 1. Phase 0：诊断探针表（I3 落地）

### 1.1 工程：新脚本 `experiments/readout_probe.py`

- 结构镜像 `eval_retrieval.py`（建数据集 → 加载模型 → 遍历查询前向）。
- **核心新增：落盘 output 层每查询激活矩阵** `A ∈ [n_query, n_db]`（3 模块各自 output 层拼接，同时保存每查询 conv 特征向量或复用 trackB 的 S npy）。
- 有了 A 与 S，**所有探针离线计算**，零重训。
- 配套 GT 构造必须与 run_inference 逐比特一致（PLAN S1.4 的共用函数原则）。

### 1.2 探针矩阵（同模型、同特征，只换读出/评分器）

| # | 探针 | 机制 | 检验假设 |
|---|---|---|---|
| P0 | cosine NN on conv 特征 | 轨B 锚（encoder 上限） | — |
| P1 | spike-forcing argmax | 轨A 锚（现状） | — |
| P2 | argmax + per-module z-score 归一 | 3 模块拼接的跨模块失衡 | H2 |
| P3 | cosine on feature_layer 输出（第二特征点） | conv→feature 段信息丢失 | H3 |
| P4 | output 层权重行作模板 × 特征 cosine | "免训练模板匹配"读出 | H1 |
| P5 | top-k 激活投票（k∈{3,5}） | 利用分数余量 | H1 |
| P6 | 线性探针（ridge，closed-form）on conv 特征 | 线性读出可达上界 | 上界 |
| P7 | 轨A分数 × 轨B分数 融合（几何平均） | 两轨互补性 | 融合价值 |

### 1.3 假设（预注册）

- **H1 分数余量塌缩**：spike-forcing 输出近似 one-hot，P@100%R≈R@1（已有证据：`table1_p100r_trackA.md` 注脚），相似地点间无可分余量；
- **H2 模块边界失衡**：3300=3×1100 模块拼接，跨模块 argmax 存在结构性偏向；
- **H3 中间层压缩**：conv 特征（4608 维）经 feature_layer（→9216）+output 层后相似度结构被破坏；
- **H4 相似地点互抑**：output 层横向竞争使近重复地点互相抑制（用 A 的列相关性检验）。

### 1.4 错误分解分析（探针表的论文级产物）

per-query 交叉表：真匹配在 S_conv 中的 rank（1 / 2-5 / 6-25 / >25）× 读出预测对错。
**"特征 top-1 但读出错"的比例 = 读出全责错误率**——这是"读出瓶颈"主张的直接量化证据。

## 2. Phase 1：无 BP 修复方案（诊断后选 1–2 个）

候选（按侵入性排序）：

| 修复 | 说明 | 纪律 |
|---|---|---|
| F1 per-module 归一化 argmax | 推理时对每模块 output 激活做 z-score 后拼接 argmax | 纯推理时变换，零训练；B0 回归天然成立 |
| F2 模板匹配读出 | output 层权重行作模板，cosine 评分替代 argmax | 零训练，推理时换评分器 |
| F3 相似度读出（track-A'） | output 层改为"查询激活与训练期锚定激活的余弦" | 需改 run_inference 读出段 → 加 `--readout_mode` 参数，默认 spike_forcing（默认行为不变，B0 回归） |
| F4 双轨融合 | 部署时 cosine 检索为主 + 读出 argmax 校验 | 混合系统，叙事降级为工程方案，慎用 |

## 3. 执行计划与成本

| 步骤 | 内容 | 成本 |
|---|---|---|
| 0.1 | 写 readout_probe.py（含 A 落盘） | 半天工程 |
| 0.2 | 训练 B5 3300 seed0 + B0 3300 seed0（探针对象） | 工作站 GPU 各 ~15-20min；本地 GTX 1650 预计 1-2h/个 |
| 0.3 | 跑探针矩阵 + 错误分解 | 离线，分钟级 |
| 1.x | 按诊断实现 F1/F2/F3 → 重评轨A | 每方案 ~1h GPU |

**试点起步**：只用 B5 3300 seed0 + B0 3300 seed0 两个模型（两者分别代表"好前端/无前端"，H1-H4 在这两个对象上若一致则机制结论不依赖前端类型，故事更硬）。

## 4. 风险与预案

- 风险：output 层激活未保存（track A 只存了 PR 曲线数据）→ 必须重训跑探针脚本，无法纯离线。**已确认事实，计入成本。**
- 风险：修复提升但 500 地退化 → 按预注册判据降级为"规模条件性修复"，仍如实可写。
- 红旗：任何修复不得引入 BP 或监督信号（卖点底线）；F3 改动 run_inference 必须保持默认路径逐比特回归。
