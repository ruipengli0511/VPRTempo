## 2. P1 范围与共同实验契约

### 候选臂（不作效果排序）

| 臂 | 固定输入 | feature 状态 | 任务标签/反馈 | 主要读出 |
|---|---|---|---|---|
| C0：固定 Gabor 直接检索 | 固定 Gabor conv 描述子 | 无 feature | 无 | conv 描述子 cosine 检索 |
| C1：冻结随机 feature | 同 C0 | 固定随机投影；W/阈值均不更新 | 无 | feature 描述子 cosine 检索 |
| C2：完整三路 triplet | 同 C0 | 同一初始 feature，按完整 triplet 更新 | 仅 spring/fall 同地点为正、异地点为负 | feature 描述子 cosine 检索 |
| C3：anchor-only／B 精确式 | 同 C0 | 与 C2 同初值，只按 B 定义的 anchor 侧精确式更新 | 同 C2 | 同 C2 |

“B 手工计算”与“相同 anchor-only 的自动梯度”只做实现验收，**不是 C4/C5 两个算法臂**。当前仓库没有 B 精确式正文；在主会话给出公式前，C3 只能保留接口和验收规范，不能补造实现。

### 公共设置建议

- 图像：28×28，PatchNorm=on、patches=7、filter=8、skip=0，与 `b5_500.json` 对齐。
- Gabor：32 通道、k=5、local WTA block=4；输出 1152 维非负向量，值域受 clamp[0,0.9] 约束。
- feature：首版容量固定为 2304，即历史 `2×1152`；所有 C1–C3 使用同一输入、同一初始化和同一读出维度。
- 模块：P1 首版固定 500 地单模块，避免 3300 地的共享前端/多模块拼接成为额外变量。
- 评价：C0–C3 使用完全相同的参考/查询 ID、GT、K 值和相似度计算；不让 output spike forcing 进入主 encoder 对比。
- 随机性：每次记录 torch/numpy/random/DataLoader seed；C1–C3 同 seed 下共享初始 feature 权重副本。P0 只验收 seed=0 的已有 B5，不预支 P1 多种子结论。
- 预算建议：先用 500 地、单 seed 做短开发；正式 epoch/batch/early stopping 由主会话定。若需要起步上限，可把 20 epochs 仅作为开发上限而非“已接受参数”，每 epoch 保存开发指标和状态差，不在本任务启动训练。

## 3. 临时 Gabor 输入方案

### 推荐：带清单的固定描述子缓存

P1 首版建议把固定 Gabor 前端与任务 feature 学习解耦：

```text
原图
  → 现有 ProcessImage（28×28, PatchNorm on）
  → 现有单样本 B5 conv/WTA/pool
  → d ∈ R^1152, d ≥ 0
  → 只读描述子缓存 + 样本 ID/配置/代码/checkpoint 清单
  → 独立 feature 学习器（批量 triplet 或 anchor-only）
```

具体做法：

1. 从 `b5_500__seed0.pth` 只读取 `conv_layer.w.weight`、`conv_layer.thr`、`conv_layer.havconnExc`，不读取旧 feature/output 作为任务学习初始化。
2. 对 P1 所有臂冻结 conv W、阈值和 ON/OFF mask；不调用 `train_conv_layer`，不做样本间 ITP 或状态更新。
3. 逐图生成 float32 描述子；缓存键至少包含代码 HEAD、有效预处理配置、B5 checkpoint SHA256、数据相对路径与 ID 列表、shape/dtype。
4. 用本次 8 个地点做 live-forward 对拍：缓存值必须与新读取前向逐元素相等；之后训练只读缓存。
5. summer 缓存仅用于开发评价；最终独立查询/winter 不在 P1 开发阶段生成或用于选择。

500 地缓存规模约为 spring/fall 1000×1152 与 summer 500×1152 个 float32，不需要保存巨大相似度矩阵或原图副本。当前 P0 **未创建该缓存**。

为什么适合最小改动：现有 conv 前向已验收且写死 batch=1；缓存避免为 triplet 立即重写 conv batch 维，也避免固定前端在每轮 BP 中重复计算。

### 阈值来源的边界

P1 最小工程方案可复用上述 500 地 B5 checkpoint 的 conv 阈值，因为它与 Gabor 核和 500 地训练角色匹配。但该阈值是历史 ITP 产物，历史运行 SHA 未知，必须在清单中写明。

若主会话要求所有 P1 组件都有新运行级 provenance，则应在 P1 另行执行一次“仅 conv 阈值校准”，只用 spring/fall 训练 ID，产出唯一共享 conv 状态供所有臂使用；这不是每个任务臂各自调参，也不属于本次 P0。不得让 C2/C3 各自更新前端阈值，否则输入不再相同。

## 4. 保留历史路径的对照方案

保留两条旧路径，不修改其语义：

1. **历史 Gabor 直通**：`b5_500.json` + `b5_500__seed0.pth` + `eval_retrieval.py` 的 `feature_point=conv`。它可复核 C0 的旧协议结果，但现有入口仍加载完整模型；新 C0 应另支持只读 conv，避免无关下游依赖。
2. **历史 feature 路径**：保留 `feature_point=feature_layer` 和 F0 `feat_stdp=off, feat_itp=off` 作为旧实现参照；不要把旧 feature ITP 当作正常发放率自适应，也不要将历史 trackA 的 raw linear 输出与轨 B clamp 表征混称。

C1 的新冻结随机 feature 可以参考 F0 的容量和初始化，但应在新目录显式生成/保存初始 W 和固定阈值，避免依赖旧检查点中缺失的配置或隐式 RNG 状态。

默认 `frontend=none`、旧 `VPRTempoTrain`、旧 STDP/ITP 和官方推理行为均不改变。

### C1：冻结随机 feature

### C2：完整三路 triplet

- 新增：spring/fall 配对 sampler、anchor/positive/negative 批量描述子读取、完整 triplet loss、feature 优化器。
- “完整三路”验收：在 loss 活跃且非退化的样例上，anchor、positive、negative 的所需梯度均按定义存在；与 C3 的差别只能来自规则本身。
- feature 学习不再调用旧 STDP、homeostasis 或 ITP；output 不参与主训练。
- 官方行为：无改变。

### C3：anchor-only／B 精确式

- 与 C2 共用数据、模型、初始化和评价，只替换更新规则。
- 在 B 正文到位前，仅定义接口、输入/输出梯度和日志字段；具体公式、margin、归一化、符号均为未知。
- anchor-only 验收需确认 positive/negative 被当作常量或按 B 定义处理，不能因共享计算图意外收到梯度。
- 官方行为：无改变。

## 7. 形状、非负性、尺度、容量、阈值与读出建议

### 形状与非负输入

固定 `d:[N,1152]`，feature 权重 `[2304,1152]`，输出 `[N,2304]`。P0 实测单图链为 `[1,784]→[1,32,24,24]→[1,1152]→[1,2304]`。Gabor 描述子经阈值 clamp/WTA/max-pool 后非负；不要在新 feature 前又执行一次 ON/OFF 取负或 PatchNorm。

### 尺度拟合

保留每核 L1=1、输入 [0,1] 和 conv clamp[0,0.9]，不在各臂单独做响应归一化。P0 24 图的 conv pre-WTA 最大值为 0.428739，说明不能按 0.9 饱和假设设阈值。

若确需额外尺度常数，只能由 spring/fall 训练 ID 估计一次、写入配置并供 C0–C3 共用；禁止按 summer 表现逐臂调整。最终检索的 L2 归一化应单独、显式记录，不与 loss 内部可能的归一化混为一步。

### feature 容量

首版固定 2304，避免同时改变宽度和学习规则。参数量随读出定义记录：linear 权重为 1152×2304=2,654,208，无 bias；若增加 bias、归一化层或 MLP，就不再是同一最小对照。

### 阈值与稳态

- conv：P1 全部冻结，使用同一共享状态。
- feature：建议主会话在 raw linear 与固定阈值 clamp 中明确二选一；训练、参考和查询必须一致。
- 不启用旧 feature ITP/homeostasis 作为 C2/C3 的隐式伴随机制。若研究问题以后需要它们，应另列消融并先修复/验证语义，不能混进 P1 首版。

### 读出

主比较用 feature/conv 描述子检索，绕过 output。历史 trackA 只作附加对照，因为它还训练 output，且 feature 前向不减阈值不 clamp；不能将其指标变化直接归因于 encoder 学习。

## 8. 候选数据 ID 与角色

### P1 500 地开发清单

完整确定性清单定义为：

```text
place_ids = [0, 1, 2, …, 499]
raw_csv_row = 8 * place_id
label = 8 * place_id
spring_file = CSV_spring 第 raw_csv_row 行
fall_file   = CSV_fall   第 raw_csv_row 行
summer_file = CSV_summer 第 raw_csv_row 行
```

| 数据 | place_id | 角色 | 可用于构造训练正负例 | 可用于开发选择 |
|---|---|---|---|---|
| spring | 0–499 全部整数 | 训练参考/anchor/positive/negative 来源 | 是 | 否（仅训练） |
| fall | 0–499 全部整数 | 训练参考/anchor/positive/negative 来源 | 是 | 否（仅训练） |
| summer | 0–499 全部整数 | 开发查询/参考检索评价 | **否** | 是 |
| winter | 未定义开发 ID | 独立最终查询 | 否 | **否** |

正负样本只由春秋训练对应构造：同一 `place_id` 的 spring↔fall 为正；不同 `place_id` 才可作负例。若采用容差或近邻负例排除，排除半径是待主会话明确的研究设定，不能用 summer 反推。

P0 已实际查看/验收的开发子集为 `[0,71,142,213,284,355,426,499]`；完整身份、文件名和标签见 `样本与前向验收.json`。P1 数据生成应从上述 500 地清单重新固定，不因旧结果好坏删点。

## 9. P1 实现验收办法（尚未执行）

1. **缓存等价**：8 个 P0 地点的 live Gabor 与缓存逐元素相等；参考/查询使用同一 transform 和 feature 读出。
2. **无隐式状态**：C0/C1 前后所有 conv/feature W、阈值和 mask 不变；C2/C3 只许预期 feature 参数变化，conv 不变。
3. **顺序与重复**：同图重复、正序/逆序读取结果一致；DataLoader 顺序可由 seed 重放。
4. **身份与负例**：所有 positive 同 place_id，所有 negative 异 place_id；训练 batch 不含 summer/winter。
5. **共享初值**：同 seed 的 C1/C2/C3 初始 feature 权重 SHA 相同；输入缓存 SHA 相同。
6. **完整 triplet 梯度**：选取 margin 活跃/不活跃样例，检查三路梯度符合定义，无不预期的冻结或零梯度。
7. **B 手工对拍**：同一小批量、同一 anchor-only 输入下，B 手工梯度与自动微分梯度按预先设定的数值容差比较；覆盖 margin 边界、零响应和归一化分支。此验收不产生新算法臂。
8. **保存恢复**：checkpoint 含有效配置和 ID 清单引用；重载后描述子与保存前一致。
9. **数值有效性**：无 NaN/Inf；记录零比例、L2、阈值和参数差，而不只记录最终 Recall。
10. **评价口径**：明确逐参考图或逐地点；所有臂同一 GT、查询分母、top-K 和归一化。
